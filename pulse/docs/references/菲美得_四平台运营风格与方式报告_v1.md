## 0. 一页结论

### 0.1 三个必须先说清的真相

**真相一：B2B 运营的目标不是"涨粉"，是"被放进询价名单"。**
机床厂采购的决策周期是 3–18 个月。运营做得好不好，看的是**你出现在多少个目标公司的视野里**，不是点赞数。用点赞数考核运营，一定会得到"数据好看、没有订单"的结果。

**真相二：四平台是四份工作，不是一份工作发四遍。**
账号角色、发帖节奏、互动方式、负责人都不同。尤其是 VK——它是运营层面唯一需要**俄语审校**的平台，比其他三个多一道工序。

**真相三：当前系统只能做到"半自动"，不要按"全自动发布"排计划。**
这一点最容易踩空，见下表。

### 0.2 当前自动化到哪一步（2026-09-17 按代码核实）

| 能力 | 状态 | 对运营的含义 |
| --- | --- | --- |
| 素材库 + 控制台（入库 / 召回 / 短文生成 / 素材包导出 / 冷却台账） | ✅ 已有 | **这是目前最有用的工具**，日常内容准备走它 |
| 发布网关（状态机 + 半自动导出） | ✅ 已有 | 发布流程有骨架，可产出"拷贝包" |
| LinkedIn / YouTube 自动适配器 | ✅ 已有 | 这两个平台的发布可以走自动链路 |
| Facebook / VK / TikTok / Reddit 适配器 | ❌ 无 | **只能半自动**：系统给文案 + 素材包 + 官方入口，人工点发布 |
| 内容生产域（A1） | ❌ 未开工 | 长文案仍需人工撰写与改写 |
| 调度域（A3） | ❌ 未开工 | **排期靠人工日历**，没有自动定时 |
| 合规域（A4） | ❌ 未开工 | 合规检查目前靠人工 + 生成侧的禁用语校验 |
| 审批控制台（A5） | ❌ 未开工 | 审批靠线下（文档 / 群）走，不是系统内 |

> **结论**：现阶段运营是**"人 + 控制台"的模式**。控制台负责挑素材、生成短文、导出素材包；人负责写长文案、审校、点发布、回填链接。
> 不要把"自动发布到四个平台"写进运营计划——这项能力目前**不存在**。

### 0.3 四平台角色分工

| 平台 | 优先级 | 运营角色 | 运营目标 | 首要指标 | 自动化 | 语言 |
| --- | --- | --- | --- | --- | --- | --- |
| **LinkedIn** | **P0-A** | **主战场（获客）** | 进入供应商询价名单 | 主页访问、资料索取、目标公司触达数 | ✅ 自动适配器 | 英语 |
| **YouTube** | P0-A | 能力证明（长视频） | 证明"能干活" | 观看完成度、询盘引用 | ✅ 自动适配器 | 英语 |
| **Facebook** | P1 | 存在感 + 群组 | 被记住、进社群 | 视频 3 秒留存、群组加入 | ❌ 半自动 | 英语 |
| **VK** | P1 | 俄语区开发 | 俄语区机床厂触达 | 社区订阅、私信询盘 | ❌ 半自动 | **俄语** |
| **Reddit** | P1 | 工程师社区试点 | 专业口碑 | 版块反馈 | ❌ 半自动 | 英语 |
| **TikTok** | P2 | 暂不投入 | （仅备素材） | —— | ❌ 不建链路 | 英语 |
| **Instagram** | P2 | 品牌佐证 | 存在感 | —— | ❌ 半自动 | 英语 |

> **本文按你的要求聚焦 LinkedIn / Facebook / TikTok / VK 四个平台**；YouTube 与 Reddit 只在涉及运营节奏时顺带提及。

### 0.4 投入估算

**最小配置：1 个人，每周约 8–10 小时**（不含拍摄）。拆解见 §8。

### 1.1 每个平台建什么账号

| 平台 | 账号类型 | 数量 | 说明 |
| --- | --- | --- | --- |
| LinkedIn | 公司主页 | 1 | 主发布主体 |
| LinkedIn | 个人号（业务员/负责人） | 1–3 | **触达远高于公司页**，必须建，且头衔要与公司页说同一件事 |

### 1.2 不要做的事

- ❌ 不要给四个平台各建一堆账号（分散且无意义）
- ❌ 不要用员工私人账号发公司内容（离职即失控）
- ❌ 不要在没有审校能力前启动 VK（俄语文案机翻直发会伤专业形象）

## 3. 运营节奏

### 3.1 一周标准节奏

| 工作日 | 固定动作 | 时长 |
| --- | --- | --- |
| **周一** | 定本周选题（2–3 个）→ 控制台按平台召回素材 → 导出素材包 | 1.5 h |
| **周二** | 写 LinkedIn 文案 → 审核 → 发布（**LinkedIn 最佳时段**） | 1 h |
| **周三** | 回复 LinkedIn 评论与私信；VK 文案翻译送审 | 0.5 h |
| **周四** | 发布 LinkedIn 第 2 帖 或 Facebook 帖；互动 | 1 h |
| **周五** | 发布 VK（俄语已审校版）；Facebook 群组分发 | 1 h |
| **周六** | （可选）TikTok 轮播 | 0.5 h |
| **周日** | 休息 / 补拍素材 | —— |

> **关键**：**周二和周四发 LinkedIn**（目标市场印度时区 09:00–11:00 为佳）。这不是玄学——B2B 工作日的上午是采购刷 LinkedIn 的时段。

### 3.2 每天必做的三件事

无论当天是否发帖：

1. **回消息**：LinkedIn 私信、Facebook 主页消息、VK 私信——**当天回**。
2. **记线索**：任何询盘、任何"能帮我看看这个件"的留言，当天记录（见 §6）。
3. **看一眼数据**：主页访问、新增关注里有没有目标行业的公司。

> 这三件事合计约 15 分钟，但它们是**运营与"只是发帖"的分界线**。

### 3.3 月度循环

| 时间 | 动作 |
| --- | --- |
| 每月初 | 定本月内容主线（4 个主题，对应 4 周） |
| 每月中 | 检查素材冷却与库存（控制台有容量预警） |
| 每月末 | **数据复盘**（见 §7）+ 安排下月补拍 |
| **每季度** | **VK 制裁名单筛查**（OFAC SDN / BIS Entity List / EU）——这是法务通过时的留痕义务 |

## 4. 内容运营流程

### 4.1 一条内容从 0 到发布的六步

```
① 选题  →  ② 挑素材  →  ③ 写文案  →  ④ 审核  →  ⑤ 发布  →  ⑥ 回填
（人）      （控制台）     （人+控制台）   （人）     （半自动）    （人）
```

| 步骤 | 谁做 | 用什么 | 产出 |
| --- | --- | --- | --- |
| ① 选题 | 运营 | §4.2 选题库 | 本周 2–3 个选题 |
| ② 挑素材 | 运营 | **素材库控制台**：选平台 → 按位次召回 | 每个位次 1 张图 |
| ③ 写文案 | 运营 | 控制台生成短文 + 人工改写成完整版 | 文案（+ 中文对照） |
| ④ 审核 | 负责人 | §4.4 审核清单 | 通过 / 打回 |
| ⑤ 发布 | 运营 | LinkedIn/YouTube 走自动；**其余半自动** | 帖子链接 |
| ⑥ 回填 | 运营 | 控制台 `/api/usage` 或发布包回填 | 留痕完成 |

### 4.2 选题库（按内容支柱）

B2B 工业铸件的选题只有六类，轮着用：

| 支柱 | 例子 | 主要平台 |
| --- | --- | --- |
| **C1 能力证明** | 大件吊装、机床加工能力、设备清单 | LinkedIn、YouTube、VK |
| **C2 工艺过程** | 白模 → 浇注 → 落砂 → 加工（证明真铸造厂） | 全平台 |
| **C3 成品细节** | 法兰、加强筋、内腔、加工面反光 | LinkedIn、VK |
| **C4 质量与检测** | 三维扫描、三坐标、**ISO9001 等资质** | LinkedIn、VK |
| **C5 交付与包装** | 缠膜、木托、装车 | 全平台 |
| **C6 痛点直击** | 铸件+粗加工一体化（**核心卖点**） | LinkedIn |

> **新增可用弹药（2026-09-12）**：`资质证书/` 已收录 **5 项证书**——高新技术企业、河北省科技型中小企业、绿色铸造示范企业、**ISO9001 质量管理体系认证**、排污许可证。
> 这直接补上了此前"无认证可写"的缺口，**ISO9001 是进入供应商短名单的敲门砖**。
> ⚠️ 使用注意：只写证书名称与范围，**不要延伸**（如不能因 ISO9001 就说"全流程质量保证"）；证书图片能否公开展示需先确认。

### 4.3 素材准备（用控制台，不用手工翻文件夹）

**推荐流程**：

1. 打开素材库控制台 → 选平台（如 LinkedIn）
2. 系统按该平台的**画面位次**逐格召回（LinkedIn 4 格、Facebook 4 格、TikTok 6 格、VK 4 格）
3. 某格挑不到 → 页面会提示**补拍**，不要随便凑一张
4. 导出**素材包**：自动按位次编号（`01_…`、`02_…`），附 `说明.txt` 与 `文案.txt`

**素材包的两个特性要知道**：

- **零修饰**：只做字节级复制，不裁不压不调色（符合领导指示）
- **导出即计冷却**：包内素材进入 **15 天冷却**，避免同一个画面反复出现；控制台会提示"本次 M 张进入冷却"

> **为什么不手工挑图**：手工挑必然反复用同一张最顺眼的图，几周后整个账号看起来"只有那一张图"。冷却机制就是解决这个问题的。

### 4.4 审核清单（发布前逐条打勾）

- [ ] 槽位 `{{ }}` 已填真值或整句删除
- [ ] 无产能 / 公差 / 材质清单（HT200 除外）/ 未核实认证 / 客户名 / 出口国家
- [ ] 无禁用语（world-class / leading / No.1 / best price / 零封号 / 保证交期）
- [ ] LinkedIn / Facebook / TikTok **正文无链接**（VK 允许）
- [ ] 图内无文字、无水印（零修饰）
- [ ] 画面内无客户名称、订单号、图纸号
- [ ] 员工面部已避开或取得授权
- [ ] 英文已由高熟练度人员复核
- [ ] **VK 额外**：俄语已审校（不是机翻直出）

### 4.5 发布方式

| 平台 | 方式 | 具体动作 |
| --- | --- | --- |
| LinkedIn | 自动或半自动 | 有适配器；半自动包会提示"确认以公司页 URN 发布" |
| Facebook | **半自动** | 复制文案 → 打开官方入口 → 上传素材 → 发布 |
| VK | **半自动** | 同上（俄语文案 + 相册图） |
| TikTok | **半自动** | 选 Photo Mode → 上传 5–6 张 → 应用内配乐 |

> **铁律**：只用平台官方入口或官方 API。**不做浏览器自动化发帖**——这违反项目铁律，且可能导致账号受限。

### 4.6 发布后必做（很多人漏掉）

1. **回填链接**：把平台贴文链接填回控制台（人工闭环留痕）
2. **标记素材已用**：控制台 `/api/usage`
3. **第 1 小时**：LinkedIn 找 5–10 位目标联系人发私信（**不带链接**）
4. **第 24 小时**：回复全部评论
5. **第 48 小时**：记录数据（见 §7）

## 5. 互动与社群运营

> **这一节是"运营"与"发帖"的真正区别。** 只发不互动，等于把传单塞进抽屉。

### 5.1 评论回复 SOP

| 情形 | 时限 | 怎么回 |
| --- | --- | --- |
| 普通提问（"what material?"） | 24 h 内 | 直接答 + 引到私信 |
| 专业质疑（"how do you control porosity?"） | 24 h 内 | **认真答工艺**，这是展示能力的最好机会 |
| 同行点赞/评论 | 48 h 内 | 简短回应 + 回访对方主页 |
| 恶意/嘲讽 | —— | **不回、不删、不争**；截图留档 |
| 询盘意图（"need a quote"） | **2 h 内** | 立即转私信，按 §6 记录 |

**回复语气**：和文案一致——工程语言、克制、不吹。

### 5.2 私信处理 SOP

```
收到私信 → 判断类型 → 报价类（转销售）/ 咨询类（运营答）/ 招聘类（转人事）/ 骚扰（忽略）
```

| 类型 | 处理 |
| --- | --- |
| 询价 | **2 小时内**回一条确认消息 + 当天转销售，附上对方公司与需求 |
| 技术咨询 | 运营答可公开的部分；涉及参数 → 要技术部确认后再答 |
| 索要资料 | 发**能力资料**（需先准备好英文版 PDF），并记录线索 |
| 招聘/合作 | 转对应部门 |

> **英文能力资料目前没有**——这是运营启动前必须补的第一件事，见 §12。

### 5.3 群组运营（Facebook）

| 步骤 | 要求 |
| --- | --- |
| 选群 | 机加工 / 制造 / CNC 类，**人数不是标准，专业度才是** |
| 读群规 | **必做**。很多群禁纯广告 |
| 发帖 | 文案改短、**不带链接**、以分享形式发 |
| 频率 | 每周 1–2 个群，不要一天进十个群狂发 |
| 互动 | 平时也要在群里回答别人的问题（**先给价值，再发内容**） |

### 5.4 主动触达（LinkedIn）

| 项 | 做法 |
| --- | --- |
| 目标 | 印度 / 美国 / 台湾机床整机厂的采购、供应链、制造工程师 |
| 方式 | 加好友 → 互动几次 → 再发私信 |
| 私信 | **第一封不带链接**，提一个具体点（"看到你们在做 XX 系列机床"） |
| 频率 | 每周 10–15 人，**不要一天加 100 人**（会被限制） |

### 5.5 绝不做的事

- ❌ 群发同一段复制粘贴的私信
- ❌ 在别人帖子下面硬推自己产品
- ❌ 用自动化工具刷粉、刷赞
- ❌ 与客户争论、删除差评

## 6. 询盘与线索归集

### 6.1 线索来源

| 来源 | 说明 |
| --- | --- |
| 帖子评论 | 有人问参数 / 要报价 |
| 私信 | 最直接 |
| 主页访问 | 通过访问记录反查目标公司 |
| 群组互动 | Facebook 群里认识的人 |
| VK 私信 | 俄语区询盘 |

### 6.2 线索分级

| 级别 | 特征 | 动作 |
| --- | --- | --- |
| **A** | 明确产品 + 数量 + 目标市场 | **2 小时内**转销售，当天回复 |
| **B** | 有产品方向，无具体需求 | 24 小时内回复，索取需求，加入培育名单 |
| **C** | 泛泛咨询 / 同行 | 正常回复，不进销售流程 |

### 6.3 移交销售必须带的字段

```
公司名 / 国家 / 联系人 / 职务 / 平台来源 / 需求描述 / 询盘原话 / 日期
```

> 没有这些字段的"线索"等于没线索——销售没法跟进。
> **工程侧对应 FR-13「线索与询盘归集」**，该模块尚未开工（`pulse/services/` 下无对应域），现阶段用表格记录。

### 6.4 VK 询盘的额外一步

俄语区询盘在转销售前，**必须先做出口对象筛查**（是否命中 OFAC SDN / BIS Entity List / EU）。这是 VK 转正时的留痕义务，不是可选项。

## 7. 数据与复盘

### 7.1 每周看板（只看这几个）

| 指标 | 为什么看 |
| --- | --- |
| 主页访问量（LinkedIn） | 唯一能反映"被看见"的硬指标 |
| 资料索取次数 | 最接近询盘的信号 |
| 新增关注中的**目标公司数** | 判断有没有触达对的人 |
| 询盘数（分 A/B/C） | 终极指标 |
| 发帖数 / 实际执行率 | 看运营有没有断档 |

### 7.2 不要看的指标

❌ 点赞数、❌ 粉丝增长、❌ 互动率、❌ 播放量（TikTok 除外，但也不进询盘 KPI）

### 7.3 每月复盘三个问题

1. **哪类选题带来的主页访问最多？** → 下月加量
2. **哪个平台带来的询盘最多？** → 资源倾斜
3. **哪一步断档了？**（没拍 / 没写 / 没审 / 没回）→ 下月修流程

### 7.4 什么信号该调整策略

| 信号 | 可能原因 | 动作 |
| --- | --- | --- |
| 连续 4 周主页访问无增长 | 内容同质化 / 发帖断档 | 换选题支柱，检查冷却机制 |
| 有访问无询盘 | CTA 太弱 / 没有能力资料可给 | 补英文资料，强化 CTA |
| 有询盘无转化 | 产品不匹配 / 参数答不上 | 补硬参数（技术部配合） |
| LinkedIn 触达突然腰斩 | 可能被限流 | 检查是否频繁带链接、是否群发 |

## 8. 人员分工与时间预算

### 8.1 最小配置（1 人可兼）

| 角色 | 做什么 | 每周耗时 |
| --- | --- | --- |
| 内容运营（1 人） | 选题、挑素材、写文案、发布、互动、记录线索 | 8–10 h |
| 审核（负责人兼） | 发布前审核（英文 + 合规） | 1 h |
| 俄语审校（外部/内部） | VK 文案审校 | 0.5 h |
| 拍摄（车间人员） | 按补拍清单拍摄 | 1.5 h/天（有拍摄任务时） |

### 8.2 必须由别人配合的事

| 事项 | 找谁 | 为什么运营自己做不了 |
| --- | --- | --- |
| 硬参数（材质 / 单重 / 公差 / 产能） | 技术部 + 生产部 | 商业机密 + 需核实 |
| 检测标准 / 探伤标准号 | 质量部 | 同上 |
| 认证对外口径 | 管理层 | 证书范围不能自行延伸 |
| VK 制裁名单筛查 | 合规 / 外贸 | 需专业判断 |
| 出口对象筛查 | 外贸 | 同上 |

### 8.3 时间预算的现实提醒

**8–10 小时/周是"只做四个平台、不做视频"的估算。**
如果加上 YouTube 与 Reddit，实际会到 12–15 小时/周。不要按 8 小时排两个人都不够的活。

### 9.1 现在就能用的

| 工具 | 用途 | 备注 |
| --- | --- | --- |
| **素材库控制台** | 上传入库、按平台召回、生成短文、导出素材包 | 目前最有价值的工具 |

### 9.2 还缺的（别指望现在有）

| 缺失 | 影响 | 临时替代 |
| --- | --- | --- |
| 自动排期 | 要人工记时间发帖 | 用日历设提醒 |

### 9.3 关于视频

当前**无剪辑人员**，且领导要求零修饰。
因此运营层面**不做需要剪辑的内容**：TikTok 走图片轮播，Facebook 发原片，其余平台发图集。若将来要视频，最省人的路径是用现成工具在手机端拼，而不是招人。

## 10. 风险与危机处理

### 10.1 内容类风险

| 风险 | 预防 | 出了怎么办 |
| --- | --- | --- |
| 误发涉密信息（客户名 / 图号 / 图纸） | 发布前过 §4.4 清单 | **立即删除**，记录时间与影响范围，上报 |
| 误发未核实参数 | 槽位制 + 审核 | 更正帖 + 删除原帖 |
| 员工未经授权出镜 | 拍摄前口头确认 | 应要求删除并道歉 |

### 10.2 平台类风险

| 风险 | 预防 | 出了怎么办 |
| --- | --- | --- |
| 被限流 | 不在正文放外链、不群发 | 减少发帖频率 1–2 周，恢复自然互动 |
| 账号被限制 | 开二次验证、不共享密码 | 走平台申诉；**不承诺"零封号"** |
| 被封号 | 管理员 ≥2 人、凭据托管 | 用备用管理员申诉 |

### 10.3 合规类风险

| 风险 | 预防 |
| --- | --- |
| VK 触达受制裁对象 | **每季度**制裁名单筛查 + 每个新询盘做出口对象筛查 |
| 俄语内容表述偏差 | 每帖审校并留档 |
| 资质超范围使用 | 只写证书名称与范围，不延伸 |

### 10.4 舆情类风险

**原则：不争论、不删除、留证据、内部升级。**
差评如果涉及产品问题，先内部核实，再以事实回应（B2B 客户看的正是你怎么处理问题）。
