## 4. 关键约束

1. **不得依赖具体 Adapter。** 你只通过各域的入口/出口契约调用。一旦 import 了 `pulse.services.publish.linkedin_adapter` 这类具体实现，其他域的改动会直接打断你的测试。
2. **KPI 口径是本项目的业务红线。** B2B 工业件决策周期 3–18 个月，目标是进入供应商短名单。用点赞数做看板会得到"数据好看但没订单"的典型失败。看板必须体现：触达、询盘、进入短名单率。
3. **审批控制台不是可选项。** FR-4 是 P0，验收标准写着"一键通过/修改/整批通过 + 审批留痕含 diff"。没有界面这条链路就交付不了——文档层最容易漏掉它。
4. **半自动导出必须在界面上可达**（契约 §7 的 `GET /api/v1/schedules/{id}/semi-auto`）。MVP 阶段部分平台发不出去，这条是主线而不是兜底。
5. `DELETE /api/v1/accounts/{id}/credential` 属管理权限操作，需与 A3 的熔断语义对齐。
